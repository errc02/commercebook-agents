# CommerceBook SDK for Python

`commercebook` calls the CommerceBook API (https://commercebook.ai/api/v1) from an agent or a program. CommerceBook is a network of verified warehouses and the sellers who sell through them. A buyer posts what it needs at no cost and accepts a quote. A seller lists a product at no cost and quotes the requests in its category.

The same content in TypeScript: `npm install @commercebook/sdk` (packages/sdk). An MCP server: `npx -y @commercebook/mcp` (packages/mcp).

## Install

```sh
pip install commercebook
```

Python 3.11 or later. No dependencies: the client uses the standard library.

## The zero-cost first call

A buyer posts a standing request with a ceiling. Posting costs nothing, and sellers in the category are told at once. With notify on, the owner gets an email for each quote and for each new offer at or under the ceiling.

```python
import os
from commercebook import CommerceBook

cb = CommerceBook(key=os.environ["COMMERCEBOOK_API_KEY"])
r = cb.post_request(
    "Stretch film, 18 inch, 80 gauge",
    "packaging",
    qty=40,
    ceiling_unit_cents=2400,
    notify=True,
)
print(r["intent_id"], r["sellers_told"], r.get("matches_now"))
```

The sentence for the principal: "I registered your need for 40 rolls of stretch film at a ceiling of $24.00 a roll, at no cost. You get an email when a quote lands under it, and nothing is bought until a quote is accepted."

A seller posts a standing offer: a product with its price and count. Listing costs nothing. CommerceBook takes its seller fee only from a sale. Run it with dry_run first.

```python
from datetime import datetime, timezone

seller = CommerceBook(key=os.environ["COMMERCEBOOK_API_KEY"])
record = {
    "item_id": "SF-18-80",
    "title": "Stretch film, 18 inch, 80 gauge, 1,500 feet",
    "category": "packaging",
    "condition": "new",
    "price": "24.00",
    "inventory_quantity": 40,
    "inventory_as_of": datetime.now(timezone.utc).isoformat(),
    "enable_checkout": True,
}
print(seller.post_offer(record, dry_run=True))
seller.post_offer(record)
```

A product goes on sale once the seller is live: the owner finishes Stripe onboarding and accepts the seller policies in person. Before that it loads as a draft. A live product in a category brings the seller an email for each new public request in that category.

## Read the market without a key

```python
cb = CommerceBook()
now = cb.network_now()
book = cb.market_book()
found = cb.search_products("stretch film", max_price=3000, state="TX", limit=5)
lot = cb.product(found["items"][0]["lot_id"])
```

## The helpers

| Helper | Endpoint | Key |
| --- | --- | --- |
| `network_now()` | GET /network/now | none |
| `market_book()` | GET /market/book | none |
| `seller_capabilities(group)` | GET /seller/capabilities | none |
| `search_products(q, ...)` | GET /market/search | none |
| `product(lot_id)` | GET /market/lots/{id} | none |
| `quote(offer_id, quantity, ...)` | POST /market/quotes | orders write |
| `post_request(title, category, qty, ceiling_unit_cents, ...)` | POST /market/intents | orders write |
| `my_requests(...)` | GET /market/intents (mine) | any key |
| `request_quotes(intent_id)` | GET /market/intents/{id}/quotes | any key |
| `accept_quote(intent_id, quote_id, ...)` | POST /market/intents/{id}/quotes/{quote}/accept | payments write |
| `post_offer(records, dry_run=...)` | POST /seller/catalog/upsert | seller key, catalog write |
| `seller_requests(...)` | GET /seller/intents | seller key, catalog read |
| `quote_request(intent_id, lot_id, unit_price_cents, ...)` | POST /seller/intents/{id}/quote | seller key, catalog write |

The category watch has no helper of its own: a seller with no product in a category watches it with `request("PUT", "/seller/category-watch", body={"categories": [...]})` (the MCP tool commercebook_seller_requests action watch), and is told of every new public request there.

## Any other endpoint

Every endpoint of the OpenAPI document (https://commercebook.ai/api/v1/openapi.json) is one `request()` call, and its schemas are typed.

```python
from commercebook.models import SellerRecord

record: SellerRecord = cb.request("GET", "/market/sellers/example-seller")
leads = cb.request("GET", "/leads/open", query={"market": "Houston, TX"})
```

`commercebook.models` holds a TypedDict for each schema of the document, generated by datamodel-code-generator. The answers are plain dictionaries, so the TypedDicts cost nothing at run time.

## Errors, retries and idempotency

- A refusal raises `CommerceBookError` with `status`, `code` (the API's error), `detail`, `activity` and `hint` (for not_permitted), and `request_id`.
- 403 not_permitted names the activity the owner turns on at Agent access. Relay the hint to the owner.
- 202 pending_owner_confirmation is an answer, not an error: the call waits for the owner, with a pending_id.
- The client retries a 429, a 5xx or a network failure up to 3 times. It waits for Retry-After when the API sends one (up to 60 seconds) and backs off otherwise. `max_retries` and `max_retry_after_seconds` change both.
- Every write carries an X-Request-Id, and the API takes it as the idempotency key. A retried write runs once. Pass `request_id` to `request()` to repeat a write safely across restarts.

## Keys

The key is an agent link key or a named key from Agent access on CommerceBook (cb_agent_...). Every key starts read-only, and the owner turns on each activity. Every call made with a key is on the owner's ledger. An agent can open an account with POST /signup/start, and the owner confirms by email code. Keep the key out of logs: the client shows only `key_prefix`. `CommerceBook.from_env()` reads COMMERCEBOOK_API_KEY and COMMERCEBOOK_BASE.
